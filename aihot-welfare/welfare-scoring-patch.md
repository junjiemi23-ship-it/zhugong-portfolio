# AIHOT 福利评分定制补丁

目标：在 AIHOT 的精选评分里加入"福利/促销"内容类型，让"新闻监控"变成"福利雷达"。
改法遵循 AIHOT 自家规矩：保留原结构（7 类型→8 类型、五轴加权、噪声压制、安全边界），只替换"什么算重要/噪声"的例子。

## 改动 1：`industry/prompts/selection-score.md`

### 1a. 内容类型列表加一类

在"二、按当前五轴独立打 0–10"上面的 7 类列表末尾加：

- `promo_welfare`：福利促销——免费额度、折扣、赠送、延长试用、邀请奖励等读者能直接领取的优惠

### 1b. 类型权重表加一行（每行权重和为 10）

| 类型 | sig | nov | cred | reson | act |
|---|---:|---:|---:|---:|---:|
| promo_welfare | 2 | 1 | 3 | 2 | 2 |

权重逻辑：cred 给 3（假福利、钓鱼优惠必须压住，呼应"福利类必须核实为官方/可靠报道才推"）；act 给 2（能马上领才有价值）；nov 只给 1（福利的新鲜度不如真实性和可领性重要）。

### 1c. "必须正常评价的价值"加一条

- 真实可领的福利：免费额度、折扣、赠送、试用延长，有明确的领取方式、门槛和截止时间，且经官方或可靠报道证实的，按其真实价值正常评分，不因"只是促销"而压低。

### 1d. "必须压住的噪声"加两条

- 福利类没有官方来源、没有明确领取方式/门槛/截止时间，或明显是钓鱼、诱导充值的，`cred ≤ 3` 且总分不得高于 40。
- 已过期、名额已满、仅限特定地区且读者多数不符合的福利，`act ≤ 3`。

## 改动 2：`.env`（OpenAI 兼容 API key 接入）

AIHOT 的模型调用走 OpenAI 兼容接口，模板见本目录 `.env.example`，关键三行：

```bash
LLM_BASE_URL=https://<你的OpenAI兼容接口地址>/v1
LLM_API_KEY=<你的 key>
LLM_MODEL=<模型名>
```

`LLM_API_KEY` **只填在你自己服务器的 `.env` 里，不要公开、不要进仓库**。

## 改动 3：部署注意事项

- 1G 内存 VPS 加 swap，Docker 构建照样跑。
- 首次导入 backfill 调用量大（官方说约半小时处理完），免费额度注意限流；先只开 3–5 个信源试跑，在 `/admin` 后台把预算熔断设好再全开。
- 向量 embeddings 不填也能跑（归组少一路线索），先不填。
- X 账号信源（SOCIALDATA_API_KEY，付费）和微信公众号（DAJIALA_KEY）先不填。
- SITE_URL 填你的 VPS 公网地址（如 `http://<你的VPS公网IP>:3000`），RSS 可给下游的推送程序当上游读。
- 参考：AIHOT 官方自己的分工是打分/归组用便宜快的 flash 模型；全走免费模型的话，跑起来后看后台"模型与评测"页的 token 用量，再决定要不要把 SUMMARIZE 这类步骤换更便宜的模型。
