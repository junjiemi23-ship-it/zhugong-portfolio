# overseas-deploy · 国内账号免备案海外直连部署法

> 状态：已实践 · 信息截至 2026-08

## 这个项目解决什么？（三问）

- **给谁看**：被国内云账号区域锁、备案要求、GFW 挡在海外平台之外的个人开发者 / 创作者。
- **解决什么**：用免费、免备案、海外直连的静态托管，让作品集 / 博客立刻对全球可达，没有 token 门禁、不用等备案。
- **产出什么**：一套可复用的部署决策树 + Cloudflare Pages 实操步骤 + SEO 迁移清单，并附「作品集如何被招聘官看到」的研究。

## 背景调研：很多人都卡在这一步

> 以下信息截至 2026-08；检索来源附在各条末尾。

- **ICP 备案是大陆服务器硬门槛**：法规限制 80 / 443 端口，大量个人站为「免备案」转 Cloudflare Tunnel / GitHub Pages / Vercel / Netlify（知乎 2026-03 多篇实战、CSDN 教程）。
- **「国内畅通、国外访问不了」是经典问题**：国内服务器部署后海外用户常卡顿 / 不可达（htstack 等行业文大量讨论）。
- **GFW 会封控海外 CDN 出口**：如 Webflow 自定义域 CDN 自 2025-11 起被 GFW 封控，需反代兜底（GitHub `shenyeah/webflow-china-speedup`）。
- **账号类型结构性分流**：腾讯云国际站 vs 国内站是分流设计——国内账号登录国际站会跳回 `console.tencentcloud.com`，**无独立国际控制台**；国际站适合海外主体 / 美元结算 / 境外服务器。这正是「国内账号无独立国际控制台、区域锁含中国大陆」的根因（腾讯云开发者社区 2026-07 文档；Hosting Verge 对比文）。
- **招聘端也在削弱外链价值**：68% 的招聘官会在面试决策前查看 LinkedIn（airesume.guru 2025-12）；技术岗面试前查看 GitHub 是常见动作（fonzi.ai 2026-05；GitHub 官方社区讨论 2025-12）。作品集外链常被跳过，需配套可见性策略（见文末「延伸」）。

**结论**：国内个人开发者 / 创作者被「备案 + 区域限制 + 账号类型 + GFW」四重因素挡在海外平台之外，是广泛痛点；招聘端「外链不点」进一步放大了这个问题。

## 决策树：先判断你属不属于本方法

1. **确认账号类型**：国际站账号（海外主体 / 美元结算）有独立国际控制台；国内账号登录国际站跳回 `console.tencentcloud.com`，无独立国际控制台 → 国际版新建不含中国大陆项目的路径作废。
2. **检查加速区域能否选「不含中国大陆」**：国内账号新建项目默认继承「含中国大陆」，且项目设置无区域编辑入口 → 不能切。
3. **结论**：国内账号在 EdgeOne 上无法获得「海外直连无 token」站点 → 转第三方静态托管。
4. **选型**见下表；Cloudflare Pages 最优。
5. **陷阱**：MCP `region:"global"` 指控制台 / 账号类型，**非加速区域**，无法靠它切区域。

### 边界 / 反例（什么情况本方法不适用）

- 目标受众主要在中国大陆 → 本方法不适用（需备案，或接受不可达）。
- 想要「大陆 + 海外」双覆盖 → Cloudflare 自定义域可海外直连，但大陆无加速、不保证可达，需明确写出取舍。
- 海外主体 / 美元结算账号走 EdgeOne 国际站是正确的；**本方法只针对国内账号**。

## 实操：Cloudflare Pages 部署

1. Cloudflare 注册 / 登录（用 GitHub 授权最顺）；
2. Workers & Pages → Pages → 连接 Git → 选仓库；
3. 构建设置：Framework 预设 None / 构建命令留空 / 输出目录 `/`（纯静态）；
4. Save and Deploy → 拿到 `<project>.pages.dev`（Region: Earth）；
5. 海外 `curl` 该域名应 **HTTP 200，无 token**。

## SEO 三件套迁移清单（旧域 → 新域）

- `index.html`：`og:url` / `canonical` / JSON-LD `url`
- `robots.txt`：`Sitemap:`
- `sitemap.xml`：各 `<loc>`

改完 `push`，Cloudflare 自动部署。

## 验证坑（沙箱环境专用）

直连 `curl` 经本地代理 `127.0.0.1:7897` 对 `.pages.dev` 返回 HTTP 000（代理 TLS 路由问题，**非站点问题**）；加 `--noproxy '*'` 后正常 200。线上用户无此问题。

## 延伸：让招聘官看到（3 条方案）

作品集外链常被跳过，配套做三件事：

1. **不点也能看到价值**：申请邮件正文直接放 3 行核心成果 + 作品集链接；PDF 简历内嵌可点击超链接（作品集 / GitHub / LinkedIn）；随邮件附作品集首页截图 / 预览图；简历放二维码（手机扫码直达）。
2. **把 GitHub 当主作品集经营**：README 门面化、真实项目分层、提交规范、每个项目 README 附部署链接（技术岗面试前查看 GitHub 是常见动作）。
3. **平台内链优先 + PDF 兜底**：LinkedIn / Boss / 猎聘资料页放内链；另提供「作品集 PDF 版」下载兜底。
