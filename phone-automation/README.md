# AI 手机操控：人机协作识图与 ADB 自动化能力验证

> 个人项目与成果：AI Agent 通过官方 ADB/scrcpy 操控 Android 手机的能力验证——连接、截图、识图定位、毫秒级触发、状态监控，以及一项原创的人机协作识图方法。

## 项目简介

本项目验证 AI Agent 使用 **Android 官方调试桥（ADB）** 与 **scrcpy** 对手机进行远程操控的完整能力链路。核心目标不是"自动化某一具体业务"，而是验证与沉淀一套**可复用的手机操控方法论**：如何稳定连接、如何读取设备状态、如何在无法直接读取界面层级（如 WebView、深色模式）时**精准定位目标元素**、如何做到毫秒级触发、以及如何识别"前端有反应但后端未成功"这类边界情况。

## 能力链路（全部实测验证）

| 能力 | 状态 | 说明 |
|---|---|---|
| 无线调试 / USB 有线连接 | ✅ | `adb pair` 配对 + USB 直连；实测 USB 有线比无线稳定 |
| 截图与设备信息读取 | ✅ | `screencap`、`wm size`、`getprop`、`dumpsys window` |
| 人机协作识图定位（原创） | ✅ | 用户在截图上标注目标 → 程序对比像素差异精确定位（见下文） |
| 设备端毫秒级触发 | ✅ | 单条 shell 命令内等待+连点，避免 PC→手机往返延迟 |
| 状态多帧监控 | ✅ | 关键时间点连续截图，观察界面状态流转 |
| 后端限制识别 | ✅ | 区分"前端 UI 响应"与"后端处理成功"（按钮激活 ≠ 操作成功）|

## 「主公标注法」：人机协作识图定位

### 问题背景

部分 App 页面（WebView、深色模式、自绘 UI）无法通过 `uiautomator dump` 获取元素坐标：
- WebView 页面只暴露根节点，无内部 DOM 信息；
- 深色模式下基于颜色的视觉检测易被大面积背景干扰；
- 纯靠 AI 视觉估测坐标，误差可达数百像素。

### 方法原理

**人类能一眼看到目标，AI 不会"看图"但擅长计算像素差异**。于是让人类在截图上用标记指出目标区域，AI 对比"原始截图"与"标记截图"的差异，用连通区域分析得到精确坐标：

1. AI 截取手机屏幕原始图；
2. 用户在截图上用黑色标记目标元素区域；
3. AI 计算两张图逐像素差异（`cv2.absdiff`）；
4. 二值化 + 连通区域分析，取最大差异块的中心 = 目标坐标；
5. `adb shell input tap` 点击验证，用户确认反馈。

### 伪代码

```python
import cv2, numpy as np

def locate_marked_button(original: str, marked: str, min_area: int = 800):
    a = cv2.imread(original)   # 原始截图
    b = cv2.imread(marked)     # 用户标注后的截图
    diff = cv2.absdiff(a, b)              # 像素差异
    gray = cv2.cvtColor(diff, cv2.COLOR_BGR2GRAY)
    _, thresh = cv2.threshold(gray, 25, 255, cv2.THRESH_BINARY)
    num, labels = cv2.connectedComponents(thresh)  # 连通区域
    best = None
    for i in range(1, num):
        pts = np.where(labels == i)
        if len(pts[0]) > min_area:
            cx = (pts[1].min() + pts[1].max()) // 2
            cy = (pts[0].min() + pts[0].max()) // 2
            if best is None or len(pts[0]) > best[0]:
                best = (len(pts[0]), cx, cy)
    return best  # (面积, 中心x, 中心y)
```

### 为什么有效

- **零语言歧义**：让用户"直接指"而不是"描述位置"（"中间偏下偏右"这类描述误差极大）；
- **不依赖 DOM**：适用于 WebView / 自绘 UI / 深色模式；
- **一次标注，全程复用**：页面布局不变时，同一坐标可复用于后续操作。

## 踩坑记录（经验沉淀）

1. **`uiautomator` 对 WebView 失效**：WebView 页面只暴露根节点，内部元素不可见 → 转向视觉方案（截图 + 差异分析）。
2. **坐标必须统一物理像素**：`adb shell input tap` 使用设备物理分辨率；分析截图前先 `wm size` 确认分辨率，避免截图缩放导致的坐标换算错误。
3. **USB 有线比无线稳定**：无线调试在热点切换 / 锁屏休眠时易掉线，关键操作优先 USB 有线，且操作前复查 `adb devices`。
4. **前端反应 ≠ 后端成功**：按钮"变亮/弹窗"只是本地 UI 响应，不代表服务器端操作成功；判断成功必须以**最终状态变化**（如目标状态被消耗）为准。
5. **脚本重写纪律**：同一脚本第 2 次失败后，先查证正确写法再改（如 bash 字符串比较毫秒不可靠，改用数值时间戳）。

## 适用边界（重要）

- **只做低风险重复辅助**：读取状态、导航、输入英文数字、低频点击；
- **交易核心 / 发消息类操作默认人工**：人手 3 秒完成的事，自动化可能 15 分钟还失败，且存在误操作风险；
- **遵守平台条款**：任何自动化操作都应在平台允许范围内，不绕过风控、不用于不正当获取利益。
