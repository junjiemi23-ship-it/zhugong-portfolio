# 主公的粮仓 · 双 AI 共管使用协议 v1.0

> 定稿：2026-08-18 · Codex（主公确认后生效）· 与 AI交流 已解决-1947 文件同文。
> 本文件为公开仓库副本，不含任何 PAT / 密码 / API Key 明文。

## 0. 适用范围与角色
- 仓库：`主公的粮仓`（公开，作品集 / 求职展示）。
- 共管方：Codex（主公主力 AI）、WorkBuddy（执行 AI）、主公（唯一决策人）。
- 规则优先级：主公最新指示 > 本协议 > 双方习惯；本协议修订需主公确认、Codex 定稿。

## 1. 目录结构约定
- 根目录：`README.md`（门面 / 导航，改动前在 AI交流 声明）。
- `docs/`：文档（含本协议副本 `共管协议.md`）。
- `codex/`：代码 / 脚本 / 配置类（Codex 为主，按子项目分）。
- `workbuddy/`：WorkBuddy 的流程 / 整理类产出。
- `projects/<项目名>/`：主公立项项目，谁主笔谁在 AI交流 声明后写入。
- 命名：目录 / 文件用小写字母、数字、连字符；中文文件名避免空格和特殊符号。

## 2. 提交信息规范
- 格式：`[Codex|WorkBuddy] <类型>: <简述>`；类型 = feat / fix / docs / chore / data。
- 示例：`[WorkBuddy] docs: 新增 README 作品集结构`。
- 必填：来源标签 + 类型 + 一句话改动；涉及文件在正文列出。
- 分支：日常小改动直接 `main`；大面积重构 / 批量改动先建 `feat/<主题>` 分支，合并前在 AI交流 声明。
- 禁止：空信息、无标签、含敏感信息的提交。

## 3. 并发 / 冲突避免与解决
- 「先声明」= 在 AI交流 写明目标文件 + 改动内容 + 预计完成时间，之后才动手；先声明者优先。
- 不同目录可并行；同一文件两 AI 不得在 15 分钟内同时改。
- 冲突：先 `git pull --rebase`；仍冲突则停手，把冲突文件 + 双方意图贴 AI交流，由 Codex 仲裁、WorkBuddy 执行；原则 = 主公意图优先、改动小者让步、可并存则分目录合并。
- 发现对方未声明改动：保留对方版本，通知对方，不擅自覆盖。

## 4. 凭据管理细则
- Codex 侧：优先 GitHub 插件 Connect（官方授权，权限由授权页控制，新会话加载）；或 classic PAT（repo，90 天）配 `GITHUB_TOKEN`。
- WorkBuddy 侧：`GITHUB_PERSONAL_ACCESS_TOKEN`。
- token 只存各自安全配置；绝不写进 AI交流 / 聊天 / 截图 / 仓库文件。
- 轮换：到期前 7 天由该侧提醒主公续期；新 token 生效后立即撤销旧 token。
- 泄漏：立即 GitHub 撤销 → 重新生成 → 通知对方 → 检查仓库 / 文件有无泄露记录并清理。
- 权限最低集：插件授权不给 admin / 删除类权限；危险操作一律走确认机制。

## 5. 危险操作确认机制
- 红线三类：删仓库 / force push / 公开敏感信息。
- 流程：AI交流 建「危险操作确认」条目（对象 / 原因 / 影响 / 撤销方法）→ 主公明确回复「同意」→ 才执行；未回复 = 禁止。
- force push：`main` 上默认禁止；确需时只允许 `--force-with-lease` 且走确认。
- 提交前检查敏感内容（密钥 / 手机号 / 姓名 / 聊天原文 / 问卷原始数据）。
- GitHub 侧建议：public 仓可设 `main` 分支保护（关闭 force push 允许）；日常小改动不强制 PR，但 force push 必须封死。

## 6. 防差错清单（提交前逐项过）
- [ ] 已 `git pull --rebase`（防分叉）
- [ ] 无敏感信息（`git diff` 复查）
- [ ] 不删 / 重建同名仓；不覆盖未声明文件
- [ ] 不 force push main；不用 `git reset --hard` 处理他人分支
- [ ] 提交信息带来源标签
- [ ] 新文件在正确目录（`codex/` `workbuddy/` `docs/` `projects/`）
- 可选加固：pre-commit 钩子扫描 `password|token|api[_-]?key|secret|BEGIN .*PRIVATE KEY`；密钥文件入 `.gitignore`。

## 7. 可追溯与对账
- 提交记录 = 来源标签 + 类型，`git log --oneline` 可查。
- 每周日 AI交流 对账：双方汇报本周改动文件，Codex 抽查一致性；问题按第 3 条仲裁。

## 8. 与主公的接口
- 写操作完成 → 相关 AI 在主公当前对话一句话汇报（改了什么、为什么）。
- 危险操作批准：主公只回「同意 / 不同意」。
- 叫停：主公说「停」= 立即停止一切仓库写操作。
- 本协议更新：任何一方提议 → AI交流 讨论 → 主公确认 → Codex 定稿并同步两份副本（AI交流 + 仓库 `docs/共管协议.md`）。
