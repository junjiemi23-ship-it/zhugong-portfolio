> 场景：EdgeOne Pages 国际版 / 纯 HTML+CSS+原生 JS / GitHub 自动部署

## 📌 作品简介（30 秒看懂）

**解决什么问题**：公开 GitHub 仓库不是「可直接部署的网站」——根目录只有 README，子目录全是骨架，直接导入部署平台会因找不到构建配置而失败；同时海外平台访问有风控、公开内容有隐私红线、域名和备案问题也让新手发怵。

**怎么意识到这个问题**：连接 EdgeOne Pages 国际版后尝试「导入 Git 仓库」，发现仓库没有 package.json、没有构建代码；此时才意识到要先回答「到底部署什么」，而不是直接点导入。

**怎么解决**：① 选「仓库即站点」路线——在根目录加一个纯 HTML 作品集入口页，再让 EdgeOne 导入 Git 仓库自动部署，**线上与 GitHub 同步、不漂移**；② 技术栈克制：纯 HTML + CSS + 约 20 行原生 JS，中英切换 + 深色模式自适应，零依赖零构建；③ 红线先行：首页不出现学校/专业/年级/姓名/手机号，联系方式经确认后只放求职邮箱 + GitHub；④ 域名先用 EdgeOne 免费默认域名，稳定后再考虑自定义域名。

**最终效果**：作品集线上可访问（`zhugong-portfolio.edgeone.cool`），7 个项目卡片可点、中英切换正常、深色模式自适应；代码 push 后线上自动更新。

## 二、问题诊断：四个连环坑

### 坑 1：仓库是 monorepo 骨架，不能直接部署

- 现象：根目录仅 README + .gitignore，7 个子目录每个只有 README，无构建代码、无顶层 package.json。
- 结论：直接「导入 Git 仓库」会因找不到构建配置失败；**必须先决定部署什么**。

### 坑 2：海外平台访问与注册风控

- 现象：网络环境、登录态复用、验证码，每一步都可能卡住。
- 解决：先打通「Chrome 登录态复用 + 分流」通道（详见仓库 `web-access/WorkBuddy-Chrome访问通道实战记录.md`）。

### 坑 3：部署方案三选一

| 方案 | 优点 | 缺点 |
|---|---|---|
| ① 直接上传 index.html | 最快 | 线上与 GitHub 不同步，违背作品集设计 |
| ② 建顶层入口页 + Git 导入（本方案） | 仓库即站点、自动同步 | 多一步首页设计 |
| ③ 先做某个子项目再部署 | 内容聚焦 | 子项目还没做完，时机不对 |

### 坑 4：红线与信息边界

- 公开作品集不能出现学校、专业、年级、真实姓名、手机号、住址、证件号、密钥；
- 联系方式放不放、放什么，需要明确规则——经确认后放**求职邮箱**（junjiemi23@gmail.com）+ GitHub。

## 三、解决方案：三步走

### 第一步：技术选型（克制优先）

| 决策项 | 选择 | 理由 |
|---|---|---|
| 部署平台 | EdgeOne Pages 国际版 | 免备案、Git 同步、免费额度、全球加速 |
| 首页技术栈 | 纯 HTML + CSS + 原生 JS（约 20 行） | 零依赖零构建，半小时可交付、长期好维护 |
| 语言 | 中英双语，localStorage 记忆 | 面向国内外雇主 |
| 深色模式 | CSS `prefers-color-scheme` 自动适配 | 不加 JS 开关 |
| 域名 | 先用免费 `*.edgeone.cool` 默认域名 | 稳定且有求职需要再买便宜域名做 CNAME |

### 第二步：入口页结构（首页定稿要点）

1. 站名「主公的粮仓 / Zhugong's Granary」；
2. Hero 定位：把 AI 工具，变成能解决问题的项目（眉标：AI 应用 · 智能体协作 · Web 落地）——**不出现学校/专业/年级**；
3. 能力三栏：智能体协作 / 轻量 Web 落地 / 调研与文档；
4. 项目 7 卡（web-access 已实践、docs 已建立，ai-chat / web-research / surveys / chat-companion 规划中，holiday-pages 待定），状态如实标注；
5. 工作方法：拆解需求 → 组织协作 → 交付与复盘；
6. 联系区：邮箱 mailto + GitHub 链接。

### 第三步：发布与验证流程

```bash
# 红线自检：确认首页不含敏感字段

# 线上验证：预览地址通常带 ?eo_token=...；返回 302 是令牌重定向，浏览器正常打开

# 期望：自定义域名后 200；预览态 302（带 Location 跳转）均非故障

# 卡片链接可用性（示例，逐个检查 7 个 GitHub 链接）

```

发布顺序：Work2 起草 → Codex + 主公审阅红线与质量 → 通过后 commit（`[WorkBuddy] feat: 作品集入口首页` / `[WorkBuddy] feat: 作品集求职向改版`）→ push → EdgeOne 导入 Git 仓库 → 线上验证 → 处理占位项目。

> 实战提示：本机 `git push` 曾因本地凭据缺失而失败；改用 GitHub Contents API（环境内 token，`perms_push=True`）提交同样可行，提交信息规范不变。自动化部署优先用 Git 导入，本地凭据缺失时 API 提交是稳妥兜底。

## 四、关键踩坑记录（实战验证）

1. **「部署什么」没想清楚就导入 = 必失败**：monorepo 骨架没有构建配置，先建入口页再导入才是正解。
2. **占位项目要留到最后**：控制台自动建的 `default-pages-zone` 先保留，正式项目验证成功后再删，避免误删配置。
3. **大陆合规**：EdgeOne 加速区域选「全球」时大陆访问需备案；选国际版免备案但大陆访问体验可能打折——按实际目标取舍。本作品集选国际站（global），面向海外与免备案诉求。
4. **本地副本 `.git` 损坏**：旧克隆落后且损坏时，直接重新克隆到干净路径，别在坏仓库上硬修。
5. **红线要逐项 grep**：发布前用命令扫一遍敏感字段，不能只靠肉眼。
6. **本地 git 凭据缺失**：`git push` 失败不一定是代码问题；确认凭据或用 API 提交兜底，别在错误路径上反复重试。

## 六、作品集制作规范沉淀（可复用清单）

从这次作品集制作中沉淀出的可复用规范（也是本仓库首页的成稿标准）：

- **双语结构**：所有文案中英双份（`lang-zh` / `lang-en`），切换按钮 + `localStorage` 记忆，默认中文；
- **深色模式**：CSS 变量 + `prefers-color-scheme` 自动适配，不做 JS 开关；
- **响应式与无障碍**：移动端断点（820px / 560px）、skip-link、`:focus-visible`、`prefers-reduced-motion`；
- **搜索展示**：`<meta name="description">` 中英简介；
- **状态如实标注**：已实践 / 已建立 / 规划中 / 待定——真正做出来才改「已实践」，不夸大；
- **红线验证**：发布前 grep 敏感字段（学校/学院/年级/专业/姓名/手机/身份证/密码/密钥），0 命中才发布；
- **部署门禁语义**：预览态访问带 `?eo_token=...`，302/401 属预期门禁而非故障；绑定自定义域名后才完全公开；
- **兜底通道**：Git 导入优先；本地凭据缺失时用 GitHub Contents API / Git Data API 提交，提交规范不变；
- **漂移检查**：发布前后对比本地与远程文件（逐字节），确认无漂移。
## 七、结论

- **仓库即站点**：入口页先行 + Git 导入，线上与仓库永远同步；
- **技术克制**：纯 HTML/CSS/JS 足够撑起作品集门面，不引入框架债务；
- **红线先行**：公开内容逐项检查，只放必要的联系方式；
- **成本控制**：免费域名起步，按需再投入；
- **兜底可靠**：Git 导入优先，凭据缺失时 Contents API 提交照样上线。
