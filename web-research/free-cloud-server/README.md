# 大学生免费领云服务器实录：从「免费试用」到「不被扣费」

> 主题：学生预算有限，如何零成本拿到可用的云服务器并安全跑起 7×24 任务
> 场景：Windows 11 / 腾讯云 Free Tier / CVM（Ubuntu 22.04 LTS）
> 整理：2026-08-19

---

## 📌 作品简介（30 秒看懂）

**解决什么问题**：在校大学生预算有限，想跑 7×24 的监控脚本，却面临四道坎——① 网上「免费服务器」教程真假难辨；② 免费试用页面同时有个人认证和企业认证，不知道怎么选；③ 轻量应用服务器和 CVM 云服务器不知道选哪个；④ 最怕免费 1 个月到期后自动转按量计费，半夜悄悄扣钱。

**怎么意识到这个问题**：本地跑监控脚本一关机就停，决定上云；在腾讯云免费试用页面看到「个人认证」和「企业认证」两类资源同时出现，一时不知道学生该走哪条路；搜索后发现「免费试用到期被扣费」是大量新用户的共同恐惧。

**怎么解决**：① 认证选型走**个人认证**（学生无企业资质，企业认证不合规风险高、投入产出比为负）；② 机型按「够用即可」选 CVM 2核2G，Ubuntu 22.04、上海地域、安全组只放行 SSH 22；③ 创建后立即**关闭自动续费**，用命令行每周对账一次到期时间，到期前 3 天复查，要么续最低配、要么销毁退还；④ 部署用密钥登录 + venv + crontab（每 6h + 随机抖动），失败也推告警，先 mock 数据跑通再考虑真实采集。

**最终效果**：0 元成本拿到可用云服务器，监控脚本 7×24 稳定运行，费用红线全程可控（免费期内 0 扣费，到期路径明确、可自动对账）。

## 一、背景与目标

我想把「二手市场价格监控」脚本（采集 → 分析 → 推送）变成 7×24 常驻任务，但：

1. 本地电脑关机/断网就停，做不到常驻；
2. 学生预算有限，不想为它买服务器；
3. 目标 = 找到**真实可用**的免费云资源 + 跑起来 + **绝不踩「免费变收费」的坑**。

## 二、问题诊断：四道坎

### 坎 1：免费资源真假难辨
- 现象：搜「免费云服务器」出来一堆教程，点进去多是引流标题，实际只是首月试用，配置还藏限制。
- 判断：以**官方免费试用页面**为准，不看二手教程的「永久免费」说法。入口从官网 `cloud.tencent.com` 首页/导航的「免费试用」「新人专区」进入（活动页链接会变，以官网入口为准）。

### 坎 2：个人认证还是企业认证？
- 现象：腾讯云 Free Tier 页面同时出现「个人认证」和「企业认证」两类免费试用，企业专享机型看起来更香。
- 分析：学生没有企业资质；企业认证流程复杂、大概率不合规，还会引入账号与税务管理麻烦。**企业专享机器的「免费」不值这个折腾成本**。
- 实操：个人实名认证走 `console.cloud.tencent.com/developer/auth`，个人实名（身份证）即可，登录用**微信扫码**最省事。

### 坎 3：轻量应用服务器 vs CVM
- 现象：2核4G5M 轻量（个人认证 + 会员专享）和 CVM 2核2G3M 都免费可领。
- 分析：监控脚本每 6h 跑一次、内存峰值 <512MB——2核2G 绰绰有余；谁「立即可用、0 元」就领谁，不为多出来的余量重走流程。
- 补充经验：轻量应用服务器（Lighthouse）和 CVM 是两套产品，控制台入口、计费项、到期销毁路径**都不在同一处**；领的是哪个，就到哪个产品控制台去管，别混。

### 坎 4：到期自动扣费
- 现象：免费时长 1 个月，很多教程没提「到期不处理会自动转按量计费」。
- 红线：**免费 ≠ 永久**；到期不续费必须手动销毁/释放。

## 三、解决方案：三步走

### 第一步：认证与机型选型（决策链）

| 决策项 | 选择 | 理由 |
|---|---|---|
| 认证 | 个人认证 | 学生无企业资质；企业认证不合规风险高、投入产出比为负 |
| 机型 | CVM 2核2G / 3M | 监控脚本资源需求极低，够用即可 |
| 地域 | 上海（ap-shanghai） | 访问闲鱼/拍机堂等大陆站点顺畅 |
| 镜像 | Ubuntu 22.04 LTS | 长期支持；不要 CentOS（旧版已 EOL） |
| 系统盘 | 50GB SSD | 免费期内不产生费用，保留余量 |
| 安全组 | 入站只开 TCP 22 | 最小攻击面，不放 80/443/3389 |

### 第二步：部署（密钥 + 定时 + 告警闭环）

```bash
# 服务器端：建 venv 并安装依赖
python3 -m venv ~/monitor/venv
source ~/monitor/venv/bin/activate
pip install pyyaml requests        # 真实采集再加 playwright

# 时区必须设成北京时间，cron 才按预期跑
sudo timedatectl set-timezone Asia/Shanghai

# crontab：每 6h 跑一次，加随机 ±30 分钟抖动；失败也要推告警
0 */6 * * * sleep $((RANDOM % 1800)); cd ~/monitor && ./venv/bin/python main.py >> run.log 2>&1
```

告警推送（Server酱，失败/成功都推一条，避免「静默失败 = 白跑」）：

```python
# push.py：Server酱 推送封装，key 从环境变量读取，绝不写进代码/仓库
import os, requests

def push(title: str, content: str = "") -> None:
    key = os.environ["SERVERCHAN_KEY"]
    requests.post(f"https://sctapi.ftqq.com/{key}.send",
                  data={"title": title, "desp": content}, timeout=10)
```

安全细节：SSH 用密钥对（或强密码）；Server酱 key 放环境变量/`.env`，**不进代码、不进仓库**；SQLite 每周自动备份一份到本地/网盘。

### 第三步：费用红线（防「免费变收费」）

1. 创建后立即在 AI交流/日历设提醒「到期前 3 天复查」；
2. 控制台检查并**关闭自动续费**（免费试用默认一般无自动续费，但要确认是否勾选过「到期转包年包月」）；
3. 到期处理二选一：续最低配 / 控制台 → CVM 实例列表 → 更多 → **销毁/退还**（销毁前先备份 SQLite 与脚本）。

**把对账命令化**（比只在日历记一笔更可靠，每周自动看一次到期时间）：

```bash
# 本地安装腾讯云 CLI（一次性）
pip install tccli
tccli configure   # 输入 SecretId / SecretKey；或用 tccli oauth login 走微信扫码

# 每周对账：查 CVM 实例的到期时间与状态（region 按实际改）
tccli cvm DescribeInstances --region ap-shanghai
# 看输出里的 ExpiredTime / InstanceState，到期时间记进提醒
```

## 四、关键踩坑记录（实战验证）

1. **「免费试用」≠「免费永久」**：免费期结束后若不处理，实例可能转按量计费产生费用——必须关自动续费 + 到期前复查（用上文的 `tccli cvm DescribeInstances` 每周对账更稳）。
2. **免费资源是「限量/先到先得」，不是随时都有**：新人免费试用常见「限时抢」「先到先得」，看到页面没货别慌，多刷新或次日再看；这个「抢」的属性很多教程不讲，容易让人以为是自己操作错了。
3. **企业认证陷阱**：页面用「企业专享」做诱饵，但学生去搞企业认证既不合规又费时，领到的机器和个人的并无本质差异。
4. **轻量 vs CVM 是两套体系**：控制台入口、计费、销毁路径都不同，领错产品会找不到自己的实例在哪。选型时先想清楚要哪个，再进对应控制台。
5. **静默失败 = 白跑**：定时任务如果失败不告警，等于监控没跑——所以失败也要推一条 Server酱 告警（代码见上文 `push.py`）。
6. **数据中心 IP 风控**：真实采集建议留在本机，服务器机房 IP 容易被目标站点风控，服务器长期只做 mock/汇总/推送。
7. **销毁前先备份**：销毁不可逆，销毁前把 SQLite、脚本、`.env`、crontab 都备份出来：`crontab -l > crontab.bak`，再点销毁。

## 七、结论

- **免费资源真实可用**，但必须以官方页面为准，警惕「永久免费」标题党；免费试用常是**限量/先到先得**；
- **认证选型**：学生走个人认证，不为企业专享的免费机器冒合规风险；
- **费用红线**：关自动续费、用 `tccli cvm DescribeInstances` 每周对账到期时间、该销毁就销毁——免费试用才不会变成账单；
- **工程落地**：密钥登录、最小安全组、定时任务 + 告警闭环、先 mock 后真实采集、销毁前先备份。
