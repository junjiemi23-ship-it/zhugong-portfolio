# 快速上手：能跑起来的最小配置

你不需要完美的配置，你需要一个保守的、以后可以放宽的配置。
五步，按顺序来——第 5 步不许跳。

## 1. 让两端先进入同一个私有网络

两端（你的电脑和云机）都装 Tailscale（或你信任的私有组网），在管理后台
批准云机设备，确认两边能看到对方的私有 IP（如 `100.x.y.z`）。

*为什么先做这步：* 不开公网端口、不做端口转发，扫描器无处可扫。
如果你说不清你的替代方案为什么同样封闭，就别用替代方案。

## 2. Server 只绑私有 IP，token 只走环境变量

控制 server **只绑**私有 IP。鉴权 token 放环境变量或 `0600` 文件——永不进
代码、聊天、截图。启动后从对端验证：私有 IP 通，公网方向无监听。

## 3. 白名单先只放一两个 runner

先放一两个执行 agent 进白名单（JSON：名字 → 可执行文件 + 固定参数），
每个显式 pin 到免费档模型。runner 以后可以加；但在被证明可信之前，
每个条目都是攻击面。

## 4. 每个 runner 用最小任务验证

发一个最小的真实任务（"在 Y 目录建一个内容为 X 的文件，然后汇报"），
走完完整闭环：派发→跟踪→验收→建议。重点盯**静默零执行**
（exit 0，实际啥都没跑）。等基础操作变得无聊了，再放宽。

## 5. 第一天就开审计日志

Append-only，记在本地，每次调用（含被拒绝的）都记。凌晨两点你会感谢这条。

## 保守默认值（在感到无聊之前一直用）

- 白名单先行：不在白名单里的，不许跑。
- 默认异步：长任务永不阻塞对话。
- 派真正的活之前，先把验收清单写好。
- 卡住的任务只告警一次，然后人工决定。
- Token 卫生是二值的：泄露一次 = 立即轮换，没有例外。

当以上全部变得波澜不惊，你就可以放宽了——加 runner、放权限、
自动化更多。不是之前。
