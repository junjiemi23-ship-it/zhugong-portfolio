# 接入清单（按顺序）

每一步都有验收标准：没达标不进下一步。小步快跑，别一次全开。

## 第 1 步：连账号（只读先行）

- [ ] 连接邮件、日历（或你常用的账号）
- [ ] 先只给读权限，验证助手能查到正确信息
- [ ] 明确约定：写操作（发邮件、建日程）先审批

**验收**：问它"你下周三下午有什么安排"，答案对了再往下走。

## 第 2 步：配对手机

- [ ] 在助手 App 里配对你的手机
- [ ] 发一条测试指令，确认能收到回复和进度

**验收**：出门在外发一句话，回家能看到结果。

## 第 3 步：明确执行层分工

- [ ] 默认执行层 = 助手云电脑（L0）：查资料、跑代码、做文件
- [ ] 只有"必须在你电脑上干的活"才走 PC（L3）
- [ ] 私有桥接搭好之前，L3 保持断开——别为了"全都要"留安全口子

**验收**：你能一句话说清"这类活走 L0，那类活走 L3"。

## 第 4 步：跑通第一个定时任务

- [ ] 选一个低风险、高频、结果可验证的任务（推荐：每日资讯推送）
- [ ] 定好时间、内容标准、打扰纪律（见 [scheduling.md](scheduling.md)）
- [ ] 先跑 2 天看数据，再决定加不加第二个

**验收**：连续 2 天准时收到，结果可用，没被打扰到。

## 第 5 步：跑通 dispatch → accept 闭环

- [ ] 用 [任务指令模板](../prompts/task-template.md) 下达第一个多步骤任务
- [ ] 要求助手按"派发→跟踪→验收→汇报"四步走
- [ ] 验收用独立标准，不只听 agent 的一面之词

**验收**：任务完成且有证据链（做了什么、依据是什么、风险在哪）。

## 之后

- 每加一个账号/设备/定时任务，重复"小步+验收"。
- 调度方法论进阶见 [agent-dispatch-kit](../agent-dispatch-kit/)。
