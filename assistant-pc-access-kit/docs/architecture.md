# 四层接入架构

```
                    ┌─────────────────────────┐
                    │        你（一句话）        │
                    └────────────┬──────────────┘
                                 │ 手机 / 任意聊天入口
                    ┌────────────▼──────────────┐
                    │     AI 助手（理解意图）     │
                    │ 拆解任务 → 选执行层 → 跟踪  │
                    │      → 独立验收 → 汇报     │
                    └─┬───────┬────────┬────────┘
                      │       │        │
           ┌──────────▼─┐ ┌───▼────┐ ┌─▼──────────┐
           │ L0 云电脑   │ │ L1 账号 │ │ L2 手机    │
           │ 终端/浏览器 │ │ 邮件/日历│ │ 遥控器+回执 │
           │ 文件系统    │ │ 按需授权 │ │ 配对      │
           └────────────┘ └────────┘ └────────────┘
                      │
           ┌──────────▼───────────────────┐
           │ L3 你的 PC（私有桥接）        │
           │ 派任务给本机智能体干活        │
           │ 跑脚本 / 整理文件 / 批量处理   │
           └──────────────────────────────┘
```

## 各层说明

### L0 · 助手自己的云电脑
助手本体运行环境：终端、浏览器（含登录态）、文件系统、定时调度，7x24 在线。
适合：查资料、跑代码、做表格、跨网站操作。**优先用这一层**，别什么都往你电脑上堆。

### L1 · 你连上的账号
邮件、日历等连接器。原则：
- 先只读，后按需放开写权限；
- 读日历了解你，写日程/发邮件先审批；
- 授权一次，长期有效；撤销也在同一处。

### L2 · 你配对的手机
配对后手机是唯一的指令入口和回执通道。在哪都能下指令，进度、结果、待审批事项都回到手机上。
纪律：重要事项只说一次，不追 ping；攒成一批说。

### L3 · 你的 PC（私有桥接）
你的电脑变成助手的手，专干"必须在你电脑上干的活"：
跑本地脚本、整理本地文件、调用本机智能体（opencode / codex / 各类 CLI）。
闭环四步：**派任务 → 跟踪进度 → 独立验收 → 回来汇报**。
调度方法论见 [agent-dispatch-kit](../agent-dispatch-kit/)。

## 任务流向（例子）

> "每天早上 9 点把 AI 圈重要动态推给我"

1. 你一句话下达（L2 手机）。
2. 助手拆解：信源采集 → 评分筛选 → 定时推送。
3. 采集评分放在 L0 云电脑跑；推送走 L2 回到你手机。
4. 定时任务每天自动触发（见 [scheduling.md](scheduling.md)），你睡觉它干活。
5. 推送前独立核验，不达标就安静（打扰纪律）。

## 设计原则

1. **执行层就近**：能在 L0 干的，不打扰 L3。
2. **权限渐进**：先只读，跑顺了再按需放开。
3. **闭环验收**：agent 说 done 不算 done，独立标准验过才算。
4. **打扰纪律**：没达到标准就安静；告警一天最多一次。
