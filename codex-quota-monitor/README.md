# Codex 额度刷新监控（codex-quota-monitor）

> 零依赖单文件 Python 定时巡检脚本：盯 AI 额度/状态信号的公开动态，状态「翻转」时通过邮箱推送给用户；已在云服务器 7×24 稳定运行。

## 背景与问题

- AI 桌面端额度的刷新/发放没有主动通知入口，社区信号（状态页、推文）零散且需要人工盯；
- 公共镜像类信号源网络可达性不稳定，单一数据源不可靠；
- 推送需要「状态翻转才提醒一次」：既不打扰，也不漏报新一次刷新。

## 方案概览

- **单文件 Python**（仅标准库，零第三方依赖），cron 定时巡检；
- **信号源分级**（按优先级顺序尝试，失败自动跳过）：
  - tibogpt.com 状态页（PROBABLY / YES / NO 判定）——主信号（公共镜像不可达时的零成本替代）
  - xcancel / nitter 公共镜像推文流（多实例故障转移）——完整推文原文信号
  - Redlib 社区旁证、IT之家 RSS——预留开关（后续接入）
- **判定状态机**：观察 → 疑似 → 高度疑似 → 已确认
- **通知通道**：SMTP 邮箱（QQ 邮箱 465 SSL）为主通道；Server酱代码保留、默认关闭；`dry_run` 支持安全演练
- **状态与事件落盘**：`state.json`（上次信号状态）+ `events.jsonl`（每次巡检事件日志）

## 关键工程点

1. **翻转判重（核心）**：`last_tibo` 与上次相同 → 不推送；状态翻转（NO ↔ PROBABLY/YES）→ 才推送一次。修复了「冷却期过后状态不变仍重复推送」的缺陷。
2. **24h 防抖**：抑制 YES/NO/YES 抖动误报；防抖期内不更新 `last_tibo`，确保防抖期过后的真实翻转仍能触发推送。
3. **三场景单测**：`--selftest` / `--test-tibogpt`（不联网、不写文件、不发信），覆盖「状态不变不推 / 翻转推一次 / 防抖抑制」。
4. **多源故障转移**：公共镜像按序尝试，网络不可达自动跳过，主信号可配置切换。

## 部署与验证（2026-08-22 全链路通过）

- 云服务器 `/opt/codex-monitor/`，cron `0 10 */3 * *`（每 3 天 10:00 巡检一次）；
- 配置 `config.yaml`（权限 600，密钥由用户本人填写，不落仓库/聊天）；
- 三场景实测：

| 场景 | 结果 |
|---|---|
| 状态不变、冷却过期 | 静默，不推送 ✅ |
| NO → PROBABLY（新刷新） | 推送 1 次 ✅ |
| 防抖期内 YES/NO 抖动 | 静默，`last_tibo` 保留 ✅ |

- 真实发送链路验证：测试邮件已送达收件箱；
- **公开副本 `monitor_codex.py` 与线上部署版 MD5 完全一致**：`b086c2678d5389f7ddc6b9a40823d776`。

## 使用

```bash
python monitor_codex.py --once          # 单次巡检
python monitor_codex.py --selftest      # 离线自测
python monitor_codex.py --test-tibogpt  # tibogpt 翻转判重单测
python monitor_codex.py --test-push     # 测试邮箱推送链路
cp config.yaml.example config.yaml      # 填写 smtp_user/smtp_pass/to_email 并 chmod 600
```

## 隐私与安全

- 仓库内**不含任何密钥/授权码/API Key**：配置模板留空占位；
- 不含真实个人邮箱、服务器地址、账号信息；
- 推送目标与凭据只存在于使用者私有 `config.yaml`（权限 600）。
